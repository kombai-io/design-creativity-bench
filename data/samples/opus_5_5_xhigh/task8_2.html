      How it works
      
      
      Patch any provider into a disposable endpoint. Route it wherever you're debugging.
      
      
      No deploys and no log spelunking. You don't have to ask a customer to "send it again". Patchbay stays between the provider and your handler for as long as you need it, then goes away.
      
    
      
    
      
      
      01
      Spin up an endpoint
      One click or one API call gives you a unique HTTPS URL like pb.patchbay.cloud/e/7f3k-orchid-91. It lives for 24 hours by default, and you can extend it to 7 days.
      
      
      02
      Point your provider at it
      Paste the URL into Stripe, GitHub, Shopify or your own service. Every request is captured with its headers, body and timing, and gets a signature check.
      
      
      03
      Replay, edit, break
      Resend any event to staging, a preview deploy or a tunnel. Change fields, or inject duplicates, bad signatures and slow deliveries.
      
      
      04
      Share and ship
      Give support a session link. Then copy a generated handler that already verifies the signature for that exact event.
      
    
      

    
      
      
      
      One endpoint, many sources. Every event is captured once and can be replayed any number of times.Replays are re-signed with each target's secret.
      
    
      
  
      

      


      
  
      
    
      
      
      What you can do
      
      
      Everything between "the provider sent it" and "our handler did the right thing".
      
    
      

    
      
      
      
        
      01 · Replay & modify
      
        
      Reproduce the exact request, then change one thing.
      
        
      You don't need a new test order to trigger another delivery. Replay the captured event byte for byte, or edit a field and see how your handler reacts. Every replay is kept alongside the original, so you can see which change fixed it.
      
        
        
          
      • Replay to staging, preview deploys or a tunnel to your machine
        • 
          
      • Edit JSON payloads with a live diff against the original
        • 
          
      • Replays are re-signed with the target's secret, so verification still runs

      02 · Failure scenarios
      
        
      Break it on purpose, before a provider does it for you.
      
        
      Providers retry, reorder and duplicate deliveries, and they drop connections. Run a captured event through a set of failure scenarios and see which ones your handler survives, before you connect it to production.
      
        
        
          
      • Duplicates, out-of-order delivery, tampered and stale signatures
        • 
          
      • Provider timeout budgets, e.g. Shopify's 5-second limit
        • 
          
      • Save scenario runs and re-run them after every fix
        •

      04 · Code snippets
      
        
      A handler written from the event you actually received.
      
        
      Pick any captured event and Patchbay writes a handler for it. The handler verifies that provider's signature, parses the payload and notes the real values it saw. Patchbay also saves the event as a test fixture, so your CI keeps checking against it.
      
        
        
          
      • Node.js, Python and Go in the beta
        • 
          
      • Signature checks that use the provider's official SDK when one exists

import express from "express";
import Stripe from "stripe";

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY);
const app = express();

app.post("/webhooks/stripe", express.raw({ type: "application/json" }), async (req, res) => {
  let event;
  try {
    event = stripe.webhooks.constructEvent(
      req.body,
      req.get("stripe-signature"),
      process.env.STRIPE_WEBHOOK_SECRET
    );
  } catch (err) {
    return res.status(400).send(`Webhook signature failed: ${err.message}`);
  }

  if (event.type === "invoice.payment_failed") {
    const invoice = event.data.object;
    // Captured: customer "cus_R4mZ8kLq2Xp", amount_due 4900, attempt_count 2
    await markPastDue(invoice.customer, {
      invoiceId: invoice.id,
      attempt: invoice.attempt_count,
      nextAttemptAt: new Date(invoice.next_payment_attempt * 1000),
    });
  }

  res.sendStatus(200);
});

import os
from datetime import datetime, timezone

import stripe
from fastapi import FastAPI, HTTPException, Request

app = FastAPI()
WEBHOOK_SECRET = os.environ["STRIPE_WEBHOOK_SECRET"]


@app.post("/webhooks/stripe")
async def stripe_webhook(request: Request):
    payload = await request.body()
    signature = request.headers.get("stripe-signature", "")
    try:
        event = stripe.Webhook.construct_event(payload, signature, WEBHOOK_SECRET)
    except (ValueError, stripe.error.SignatureVerificationError):
        raise HTTPException(status_code=400, detail="Invalid signature")

    if event["type"] == "invoice.payment_failed":
        invoice = event["data"]["object"]
        # Captured: customer "cus_R4mZ8kLq2Xp", amount_due 4900, attempt_count 2
        await mark_past_due(
            invoice["customer"],
            invoice_id=invoice["id"],
            attempt=invoice["attempt_count"],
            next_attempt_at=datetime.fromtimestamp(invoice["next_payment_attempt"], tz=timezone.utc),
        )

    return {"received": True}
      

      // Generated by Patchbay from evt_1RWk2v… (Stripe · invoice.payment_failed)
package webhooks

import (
	"encoding/json"
	"io"
	"net/http"
	"os"

	"github.com/stripe/stripe-go/v79"
	"github.com/stripe/stripe-go/v79/webhook"
)

func StripeHandler(w http.ResponseWriter, r *http.Request) {
	payload, err := io.ReadAll(io.LimitReader(r.Body, 65536))
	if err != nil {
		http.Error(w, "could not read body", http.StatusServiceUnavailable)
		return
	}

	event, err := webhook.ConstructEvent(payload, r.Header.Get("Stripe-Signature"), os.Getenv("STRIPE_WEBHOOK_SECRET"))
	if err != nil {
		http.Error(w, "invalid signature", http.StatusBadRequest)
		return
	}

	if event.Type == "invoice.payment_failed" {
		var invoice stripe.Invoice
		if err := json.Unmarshal(event.Data.Raw, &invoice); err != nil {
			http.Error(w, "malformed invoice", http.StatusBadRequest)
			return
		}
		// Captured: customer "cus_R4mZ8kLq2Xp", amount_due 4900, attempt_count 2
		markPastDue(r.Context(), invoice.Customer.ID, invoice.ID, invoice.AttemptCount)
	}

	w.WriteHeader(http.StatusOK)
}

      FAQ
      
      
      Questions teams ask before joining.
      
      
      Something else? Email beta@patchbay.cloud. A founder usually replies within a day.
      
    
      
    
      
      
      
        Is Patchbay Cloud meant to sit in front of production traffic?
        
      No. Patchbay is for testing and debugging integrations before they reach production, and alongside it when something breaks. Point your providers' test-mode or staging webhooks at a temporary endpoint, and promote your handler once it passes. There are no delivery guarantees or production SLAs during the beta.
      
      
      
      
      
        How long do endpoints and captured events last?
        
      Endpoints expire after 24 hours by default, and you can extend them to 7 days. Captured events and session history are kept for 14 days, then permanently deleted. You can delete an endpoint and all of its events at any time.
      
      
      
      
      
        What happens to sensitive data in payloads?
        
      Payloads are encrypted in transit (TLS 1.2+) and at rest (AES-256). Redaction rules mask fields such as emails, tokens and card data before events appear in shared views, and share links can be view-only. During the beta, we recommend using your providers' test modes.
      
      
      
      
      
        Which providers and signing methods work?
        
      Any service that sends webhooks over HTTP(S). Signature presets cover HMAC-SHA256 and HMAC-SHA1 (hex or base64), timestamped schemes such as Stripe's t=…,v1=…, the Standard Webhooks spec, and bearer-token or Basic auth. Asymmetric signatures (Ed25519, RSA) are planned for general availability.
      
      
      
      
      
        Can I replay events to my laptop?
        
      Replays go to any HTTPS URL that's reachable from the internet. That can be a staging environment, a preview deploy, or a tunnel you already use to expose localhost. Replays are re-signed with the target's secret, so your verification code runs just as it would for the real provider.
