The waiting problem

The contract is agreed on Monday. The endpoints ship three weeks later.

01

Frontend builds on guesses

Hand-written fixtures drift from the spec, and nobody sees the drift until integration week.

02

Edge cases are hard to reach

QA most needs to test timeouts, 429s and declined cards, and those are the hardest cases to trigger on staging.

03

Staging is a single point of failure

One broken deploy stops every demo, test run and prototype at the same time.

How it works

From spec to shareable endpoint in three steps

You already have the contract. MorrowSpec makes it callable, and keeps it up to date when the spec changes.

  1. 1

    Bring your spec

    Upload an OpenAPI file, or connect a code repository and choose the branch and file path. MorrowSpec watches that file for changes.

    Upload file Sync from repo
    acme/orders-service · main● watching
    # specs/openapi.yaml
openapi: 3.1.0
info:
  title: Orders API
  version: 2.14.0
paths:
  /v1/orders/{id}:
    get:
      operationId: getOrder
  2. 2

    Get a hosted mock API

    Every path and documented response becomes a live endpoint at a URL you can share. Response data follows your schemas, formats, enums and examples.

    Change the spec and the mock updates. Each change is labelled as added, changed or breaking, so a new or removed field doesn't catch anyone out.

We're starting narrow on purpose, with OpenAPI-based REST APIs only. Here's exactly what invited teams get.

Included in the private beta

FAQ

What teams ask before joining

Have a question that isn't answered here? Email beta@morrowspec.dev and a founder will reply.

Which API specifications does the beta support?

The private beta supports OpenAPI 3.0 and 3.1 specs that describe REST APIs, in YAML or JSON. GraphQL, gRPC, AsyncAPI and SOAP aren't supported at first.

Does my spec need to be complete?

No. MorrowSpec mocks whatever paths are defined. It uses your examples where you've written them. Where you haven't, it generates data from the schema's types, formats and enums. Add detail over time and the mock gets better with every sync.

How does repository sync work?

Connect a repository, then choose a branch and the path to your spec file. When that file changes, MorrowSpec updates the mock and labels each change as added, changed or breaking. To keep an environment stable for a demo, pin it to a specific version.

Can different teams use different scenarios at the same time?

Yes. Each environment has its own URL and its own active scenario. QA can run failure cases in one environment while frontend works against the happy path in another. For one-off requests, you can also choose a scenario with a request header.

Do you need access to our services or production data?

No. Mock responses are generated from your spec and its examples. MorrowSpec never calls your running services or databases.

What does the private beta cost?

Nothing. The beta is free for invited teams. We'll publish pricing before general availability, and beta teams will hear about it first.

How are teams chosen from the waitlist?

We invite teams in cohorts. Cohort 1 goes first to teams that already have an OpenAPI spec for a REST API and more than one role that would use the mock, for example frontend and QA. After that, a new cohort goes out every two weeks.
