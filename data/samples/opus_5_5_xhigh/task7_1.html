How it works

Every pull request gets its own production-like environment

Connect Branchglass to your repository and cloud account once. After that, every pull request gets an isolated preview with a shareable URL. The preview updates with every commit and is removed when the PR is merged or closed.

Where it fits in your workflow

You keep your editor, your Git host and your CI/CD pipeline. Branchglass reacts to pull request events and manages the environment in between, then reports back where your team already works.

  • Your existing tools
  • Trigger
  • Branchglass
Branchglass manages the environment for the life of the pull request
  1. Your tools Write code On a feature branch, in the editor you already use
  2. Trigger Open a pull request In GitHub, GitLab or Bitbucket, as usual
  3. Branchglass Preview environment Built in your cloud account in about 2 minutes
  4. Branchglass Review & QA Shared URL alongside your normal code review, updated on every push
  5. Trigger Merge or close Branchglass removes the environment automatically
  6. Your tools Ship to production Through your existing CI/CD pipeline, unchanged

  • Runs in your cloud account

    Previews are created in your own AWS, Google Cloud or Azure account, under your existing security policies.

  • No pipeline changes

    Your CI/CD keeps deploying to production. Branchglass only handles preview environments.

  • Safe by default

    Previews use masked data and test-mode keys, and they sit behind your company sign-in.

  • Pay only while a PR is open

    Environments are removed on merge or close, so idle previews don’t pile up on your bill.
