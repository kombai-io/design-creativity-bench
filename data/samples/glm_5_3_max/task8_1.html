// how it works

From spec to running endpoint in three moves

Point MorrowSpec at your contract. It does the rest — and keeps doing it as the spec evolves.

01

Import or sync your spec

Upload an OpenAPI specification directly, or connect a code repository and let MorrowSpec track the contract alongside your code.

supports OpenAPI 3.x · repo-sync via git
02

Get a hosted mock endpoint

MorrowSpec generates a live mock API with realistic response bodies, faithful error states, and switchable test scenarios — no stub server to write or deploy.

scenarios default · empty · error-path
03

Spec changes? Mock updates

When the underlying specification changes, the mock API updates to match. Frontend, QA, and product always test against the current contract — never a stale stub.

propagation automatic on every spec change

Private-beta scope

The beta will initially support OpenAPI-based REST APIs. Support for additional specification formats is on the roadmap — beta members will see it first and help shape it.

// capabilities

Mocks that behave like the real thing

Not a hardcoded JSON file — a working stand-in your whole team can trust.

Import or repo-sync

Bring in an OpenAPI spec as a file, or sync it straight from your repository so the mock always tracks the source of truth.

Realistic responses & errors

Response bodies, headers, status codes, and edge-case errors generated from your schema — including 4xx/5xx paths, not just the happy path.

Test scenarios on demand

Flip between realistic, empty, slow, and error scenarios to exercise loading states, retries, and failure handling in your client.

Updates with the spec

Change the specification and the mock changes with it. Endpoints, fields, and error shapes stay in lockstep with the contract — automatically.

// shared environments

One mock. Every seat at the table.

A shared environment means frontend, backend, QA, and product all test against the same contract — with a single link instead of a wiki page of curl examples.

  • Frontend builds screens against real-shaped data from day one.
  • Backend validates implementations against the same contract clients used.
  • QA rehearses error paths and edge scenarios before anything ships.
  • Product explores the API hands-on, straight from the spec.
