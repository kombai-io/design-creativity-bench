Frequently Asked Questions

Everything you need to know about the private beta

Have questions about spec support, security, or how MorrowSpec fits into your current CI/CD pipelines?

The initial private beta specifically supports OpenAPI 3.0 and OpenAPI 3.1 REST specifications (both YAML and JSON formats). Support for GraphQL schemas and gRPC Protocol Buffers is on our technical roadmap for late 2025.
You can install our native GitHub App, configure a GitLab webhook, or call our lightweight CI CLI. Whenever an OpenAPI file is modified or a pull request is merged on your selected branch, MorrowSpec automatically recompiles the contract and invalidates edge mock caches within milliseconds.
MorrowSpec does not simply emit raw placeholders like "id": "string". Our engine inspects schema formats (such as email, uuid, uri, date-time), property names (e.g., currency, billingAddress, avatarUrl), and enum constraints to generate semantically appropriate data. If you have explicit example or default tags in your spec, MorrowSpec respects those with top priority.
You can trigger any documented OpenAPI response code or named example using standard HTTP request headers (like X-Morrow-Status: 402 or X-Morrow-Scenario: expired_card) or URL query parameters (?__scenario=rate_limit). This makes automated testing in Cypress, Playwright, or Jest effortless because your test suite does not need to rewrite server stubs.
No. MorrowSpec only needs access to your public or private OpenAPI schema file. We never inspect, store, or require connections to your internal production databases or backend business logic. All mock data is dynamically generated on our edge network according to schema definitions.
