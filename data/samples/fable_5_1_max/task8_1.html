How it works

From spec to shared mock in three steps

No fixtures to hand-write, no mock server to babysit. Point MorrowSpec at your OpenAPI specification and the rest is generated — and kept current.

STEP 01

Import or sync your spec

Upload an OpenAPI specification, or connect the code repository where it lives. MorrowSpec reads the contract — paths, schemas, examples, and error responses.

openapi.yaml or acme/payments-api · main
STEP 02

Get a hosted mock endpoint

Every operation gets a live URL that returns realistic responses shaped by your schemas, along with the error cases and test scenarios your team needs to exercise.

payments.mock.morrowspec.dev/v1/orders200 realistic dataerrorsscenarios
STEP 03

Share one environment

Frontend, backend, QA, and product all point at the same environment. When the spec changes, the mock updates — no regenerating fixtures, no drift.

What you get

Mocks that behave like the real thing

Static stubs return the same happy-path JSON forever. MorrowSpec produces a mock that is realistic, adversarial when you need it to be, and always tied to the contract.

Realistic responses

Data that respects your schemas — formats, enums, ranges, nested objects and arrays. Screens look real before a single row exists in production.

Errors on demand

Every 4xx and 5xx response in your spec is one request away, so error states get designed, built, and tested instead of discovered later.

Test scenarios

Name the situations that matter — rate limits, empty results, slow responses, expired sessions — and switch between them per request.

Always current

Sync from your repository and the mock updates whenever the specification changes. What your team builds against is always the current contract.

Shared environments

One hosted environment for frontend, backend, QA, and product. Everyone sees the same API, the same data, and the same scenarios.

Spec-first, by design

The OpenAPI specification is the single source of truth for the mock, which keeps teams honest about the contract and surfaces gaps in the spec early.

Spec sync

The mock follows the spec. Not the other way around.

Hand-maintained mocks drift. A field gets renamed, someone forgets to update the fixtures, and the frontend ships against last month's contract. MorrowSpec syncs with your code repository and updates the hosted mock whenever the specification changes.

  • Import a spec file directly, or connect a repository and follow a branch.
  • Changes to the specification are reflected in the hosted mock — no manual regeneration.
  • Every consumer — frontend, backend, QA, product — is on the same version of the contract.

FAQ

Questions teams ask before joining

What exactly does MorrowSpec generate?

A hosted mock of your API, derived from your OpenAPI specification. Every operation in the spec gets a live endpoint that returns realistic responses matching your schemas, plus the error responses you've defined and test scenarios you can trigger per request.

Which kinds of APIs are supported in the private beta?

The private beta initially supports OpenAPI-based REST APIs. If your team relies on other API styles or specification formats, join the waitlist and tell us — it directly informs what we build next.

How does the mock stay up to date with the spec?

Import a spec file directly, or sync it from your code repository. When the specification changes, the hosted mock updates to match, so what your team builds against is always the current contract.

Can it return errors and edge cases, not just happy paths?

Yes. The error responses defined in your spec — 4xx and 5xx — are available on demand, and test scenarios let you exercise specific situations such as rate limiting, empty results, or slow responses.

Who on the team uses it?

Everyone who touches the API. Frontend developers build against it, backend developers publish the contract to it, QA scripts tests against its scenarios, and product uses it for realistic prototypes and demos — all from one shared environment.

What happens after I join the waitlist?

We're inviting teams in small batches. When your spot opens, you'll receive an email with access details and what you need to import your first spec. Program details, including pricing, are shared with teams when they're invited.
