How it works

Connect once. Every pull request gets its own environment.

Branchglass connects to your repository and your cloud account, then handles the rest: an isolated, production-like environment for every pull request, kept current with each commit and removed when the PR is merged or closed.

One-time setup

Connect your repository and cloud account

Point Branchglass at the repository your team works in and connect the cloud account you already deploy to. That’s the whole setup — from here on, Branchglass listens for pull request activity and does the rest.

    Open a pull request

  2. 2

    Share one URL with everyone

    Each environment comes with a shareable URL. Developers, designers, and reviewers open the same link and try the actual change in their browser — no checking out branches locally, no queueing for a shared staging server.

  3. 3

    Push, and it keeps up

    Every new commit updates the environment automatically, so reviewers are always looking at the latest state of the branch — and nobody has to redeploy anything by hand.

    c19e4d7 Handle proration when plans change mid-cycle Preview updated
    8b02f31 Add usage-based billing Preview created
  4. 4

    Merge or close, and it’s gone

    When the pull request is merged or closed, Branchglass tears the environment down. Nothing is left running, and there’s nothing for anyone to clean up.

    Merged Add usage-based billing #482
    BranchglassEnvironment removed pr-482.acme.branchglass.app

Your workflow doesn’t change. Branchglass runs on the events your team already produces — open, push, merge — so every pull request simply comes with a place to try it.
