01 WHERE IT FITS

It slots between your systems of record and everything downstream.

No new pipeline code, no cron jobs, no “sync scripts” folder. Conduit Lake reads change at the source and delivers it, shaped, wherever your stack needs it.

01

Capture change, not tables

Logical replication from Postgres, bucket events from S3, consumer groups on Kafka. Conduit Lake reads the change stream directly — no locks, no batch windows, no impact on the source.

{ "op": "insert", "src": "pg.orders", "lsn": "0/1B44F08",
  "ts": "02:14:07.331", "row": { "id": 8842, "total": 129.0 } }
02

Shape schema drift, handled

Types map through one registry. A new column upstream becomes a governed migration downstream — not a 3 a.m. page.

shape:
  on_new_column: evolve_target   # never fail the stream
  map: { created_at: timestamptz, total: numeric(12,2) }
03

Route one stream, many lands

Fan a single capture out to a warehouse, a lakehouse and an object archive at once. Each route keeps its own watermark, so a slow target never blocks the rest.

routes:
  - to: snowflake.analytics.orders   # merge by id
  - to: databricks.bronze.orders     # delta append
  - to: s3://lake/raw/orders/        # parquet archive
04

Activate downstream wakes itself

Watermarks trigger dbt runs the moment data lands, and Looker's PDTs refresh on arrival — dashboards show what happened seconds ago, not last night.

triggers:
  - on_watermark: orders  → dbt run +orders_mart
  - on_arrival: orders_mart → looker refresh revenue_live # 4.1s p50
