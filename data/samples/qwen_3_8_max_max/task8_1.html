The fine print, printed large

What the private beta ships.

▸ IN THE PRIVATE BETA

  • ✓OpenAPI 3.0 / 3.1 import — YAML or JSON, file upload or paste
  • ✓Git repository sync — the mock updates when the spec changes
  • ✓Hosted HTTPS endpoints — realistic bodies, headers, and status codes
  • ✓Scenario engine — errors, validation failures, latency spikes, rate limits
  • ✓Shared team environments — one URL for frontend, backend, QA & product
  • ✓Unlimited mock requests for the duration of the beta

▸ ON THE ROADMAP

  • ~GraphQL & gRPC sources — beyond REST
  • ~Contract drift detection — alert when the real API diverges from spec
  • ~CI assertion runs — fail the build if the contract breaks
  • ~Self-hosted runner — for air-gapped teams

The private beta will initially support OpenAPI-based REST APIs. Other interface styles arrive as the spec engine matures — waitlist members vote on what ships next.

Before you join the waitlist.

An OpenAPI 3.x document — a file you upload, YAML you paste, or a repository that contains one. If your team writes specs, you're ready in under a minute. If you don't have one yet, the beta onboarding includes a 15-minute spec rescue session.

The private beta initially supports OpenAPI 3.0 and 3.1 for REST APIs, in YAML or JSON. GraphQL and gRPC sources are the next items on the roadmap, and waitlist members help prioritize the order.
