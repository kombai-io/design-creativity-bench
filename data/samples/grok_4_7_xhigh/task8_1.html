01

The mock is a build of the spec.

Hand-written stubs drift the day the contract changes. MorrowSpec regenerates the host from the OpenAPI document you already keep.

Stub file versus a MorrowSpec environment
Question Hand-maintained stub MorrowSpec environment
Source of truth Whoever last edited the JSON file The OpenAPI document, pinned to a branch and commit
Happy path One example, often from last quarter Recorded example when the spec has one; otherwise a schema-valid body
Errors and scenarios Usually missing Named scenarios with a status, a body, and a header to force them
When the spec changes A manual edit, if anyone remembers Poll every 15 minutes, or sooner via the beta GitHub App. The URL stays put
Sharing A paste in chat One host for frontend, backend, QA, and product, with per-person keys
Drift Invisible until a demo breaks A stamp, the commits ahead, and the revision still being served
  1. 01 — Import

    Bring the contract

    Upload payments.openapi.yaml, or point MorrowSpec at northline/payments-spec, branch main, path openapi/payments.openapi.yaml. GitHub App or GitLab project token. OpenAPI 3.0 and 3.1, YAML or JSON.

  2. 02 — Host

    Stand up the endpoint

    Examples become the recorded path. You name the failures: declines, conflicts, timeouts. When the pinned branch moves, the mock is rebuilt. Median on the reference tenant, last 7 days: 14 minutes. Poll interval is 15; the GitHub App path is faster, which pulls the median under the interval.

  3. 03 — Share

    Hand out keys, not files

    Scopes in this beta: read, scenario-admin, write-spec, admin. Frontend and product usually hold read. QA holds scenario-admin. The URL does not change when the spec syncs, so CI and review notes do not rot.

07

Questions teams ask before they join.

Short answers. The same facts as the rest of this sheet, in the order people actually ask them.

What does a beta seat include?

Three hosted environments, 50,000 requests a month, GitHub or GitLab sync every 15 minutes, file upload, named scenarios, per-person keys, and a choice of us-east-1 or eu-central-1. No charge during cohort 04, which runs 18 March to 15 April 2026. 43 of 80 invites are already out.

Which specifications work?

OpenAPI 3.0.x and 3.1.x describing JSON REST. YAML or JSON. Partial specs are accepted; paths you have not described return 501 with the missing operationId. GraphQL, gRPC, AsyncAPI, and SOAP are not in this beta. If that is what you need, stay on the list for a later runtime rather than taking a seat you cannot use.

How realistic are the responses?

Happy-path bodies come from examples in the spec when those exist. Otherwise MorrowSpec generates values that satisfy the schema: types, enums, formats, required fields. Named scenarios return the status and body you pin. On the reference tenant, 96.4% of responses over the last 7 days validated against the active schema. The misses are mostly free-form additionalProperties objects, which we report rather than hide.

What happens when the spec changes?

The pinned branch is polled every 15 minutes, or sooner if the GitHub App receives a push. GitLab uses a project access token. The mock URL stays the same. If generation fails, or if main moves ahead of the last good build, the environment is stamped Drift and keeps serving the last good revision. catalog-preview is in that state now: two commits ahead, still serving a88c014, because compare_at changed type.

Who on the team can use an environment?

Anyone you issue a key to. Scopes are read, scenario-admin, write-spec, and admin. Frontend and product usually hold read. QA holds scenario-admin so they can pin failures. The person who owns the spec holds write-spec. Keys can be revoked without rotating the URL, as Camille’s was at 09:55 UTC today.

What do you do with our specification?

Stored in the region you pick, encrypted at rest, used only to build your mock. Not used to train models. Not sold. You can delete an environment and its spec from the beta console; deletion completes within 24 hours. Office-hour files sent by email are deleted after the slot notes are written.
