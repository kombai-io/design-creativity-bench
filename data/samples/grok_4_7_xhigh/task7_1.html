How it works

Open a pull request.
Get a private production.

Close it, and the environment is already gone.

Branchglass fits the review you already run. It connects to the code repository and the cloud account. Opening a pull request creates an isolated preview with production-like configuration and safe test data. Developers, designers, and reviewers get a shareable URL. New commits automatically update that environment. Merge or close, and Branchglass removes it.

01 — The loop

From a pull request to a URL, then back to nothing.

Six steps. The team only does the first connection by hand. Every later pull request runs the rest.

  1. 01

    Connect the repository and the cloud account.

    Branchglass installs on the code host and assumes a scoped role in the cloud account. It reads service definitions and production configuration so later previews can mirror them. It does not deploy into production. Northline did this once, on 12 Mar, and has not edited the role since.

    • GitHubnorthline org · checkout, web, invoicingConnected
    • AWS482193770216 · role branchglass-previewConnected
    • Slack#checkout-reviews · 18 membersConnected

    GitLab and Google Cloud are supported. This workspace does not use them. External ID nl-7f3a-22c1. Installed by Priya Nair, 12 Mar 2026, 16:22 UTC. The role may touch only resources tagged branchglass:preview. Production VPC 10.8.0.0/16 is an explicit deny.

  2. 02

    Opening a pull request starts an isolated environment.

    A pull_request.opened webhook is the trigger. Branchglass allocates a preview that does not share a network, database, queue, or hostname with production, or with any other pull request. Nobody files a platform ticket, and nobody waits on a shared staging slot.

    No route from a preview to production. No route from one preview to another. #1842 reached a URL in 4 minutes 51 seconds, next to the 4m 38s median.

  3. 03

    Production-like configuration. Safe test data.

    The environment mirrors the current production release, then applies the branch. Service versions, feature-flag defaults, and resource sizes come from release 2026.03.18. Secrets come from the preview vault, not from production. Data is a sanitized snapshot: real shape, replaced identifiers, edge cases kept.

    config     release 2026.03.18
secrets    preview/checkout/*     prod vault denied
snapshot   orders-anon-2026-03-17
size       38 GB · 1,204,883 orders
kept       2,416 failed ACH rows for retry tests
replaced   emails, card numbers, bank accounts
override   tax_quote_cache=on inside vpc 10.42.184.0/24 only

    The branch change is the only intentional drift. For #1842, that is the tax-quote cache. Production flags are otherwise copied, not invented.

  4. 04

    Developers, designers, and reviewers get one URL.

    The same link is commented on the pull request and posted to Slack. The author checks a metric, a designer opens it on a review call, a reviewer replays a failure. There is no second environment to keep in sync, and no cloud-console login to hand out.

  5. 05

    New commits automatically update the environment.

    A push to the branch rebuilds what changed and keeps the URL. Reviewers refresh. They do not hunt for a new link, and they do not reseed a database. A case found before the fix is still there after it.

    #1831 is mid-update right now: commit 9ab31d0 at 14:29, rebuild bg-1831-9, ETA 14:36. The URL still serves bg-1831-8 until the new build is healthy.

  6. 06

    Merge or close, and the environment is removed.

    When the pull request is merged or closed, Branchglass deletes the preview network, the DNS record, and the data volume. A forgotten branch does not keep billing. Across Northline’s last 30 days, that teardown took a median of 47 seconds. 213 of 216 environments are already gone. The other three are the open reviews below.

The review does not change shape. Branchglass takes the environment work out of it.

What your team still does

Your review, unchanged

  • Open the pull request in GitHub the way you already do.
  • Test on the URL Branchglass comments onto that pull request.
  • Push follow-up commits to the same branch.
  • Merge or close when the review is finished.

What Branchglass does around it

The environment, handled

  • Creates the isolated preview from the open webhook.
  • Loads production-like config and safe test data.
  • Holds the URL steady and updates it on each push.
  • Removes the environment on merge or close.
