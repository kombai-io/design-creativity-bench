How it works

From pull request to production-like preview in minutes.

Connect Branchglass once to your repo and cloud. After that, it slots into the pull-request flow your team already uses — creating, updating, and removing environments automatically.

  • ✓ Spin-up in ~2 min
  • ↻ Synced on every commit
  • ◍ Removed on merge / close

  1. OAuth your code host and cloud. Branchglass reads your service config and infra-as-code, maps env vars, secrets and networking — no migration, no rewrite.

    • 5-min setup
    • GitHub • GitLab • Bitbucket
    • AWS • GCP • Azure

  2. Every PR triggers its own namespaced environment with production-like configuration — same services, flags, and versions — seeded with scrubbed, synthetic test data. Safe to click, safe to break.

    • Automatic on PR open
    • Isolated VPC + data
    • Prod parity

  3. Branchglass posts a shareable URL on the PR. Developers, designers and reviewers open it — no local setup, no credentials chase. Comment, approve, or request changes with full context.

    • Shareable URL
    • No local setup
    • Design • PM • QA friendly

  4. New commits rebuild incrementally, so the preview never goes stale. Merge or close the PR and the whole environment — infra, data, DNS — is destroyed in seconds. No zombies, no bill creep.

    • Updates per commit
    • Destroyed on merge
    • Zero leftovers
