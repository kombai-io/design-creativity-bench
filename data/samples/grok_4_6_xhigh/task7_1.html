How it works

Every pull request gets a real cloud. Then it disappears.

Branchglass sits between your repository and your cloud account, spinning up isolated, production-like environments so engineering teams can test and review changes before they ship—without a staging queue or leftover infrastructure.

  1. 01 Once

    Connect the repo and the cloud

    Branchglass links to the team’s code repository and cloud account. It becomes a quiet layer in the stack you already run—no new branching model, no extra environment to babysit.

    Integration
    Repository acme/checkout
    Cloud account prod-like VPC
  2. 02 Automatic

    Open a pull request. That’s the trigger.

    The moment a PR is opened, Branchglass provisions an isolated preview environment. No ticket, no shared staging box, no “is anyone using QA right now?”

    Trigger
    Open #482 · 2 min ago

  3. 03 Faithful

    Production-like configuration. Safe test data.

    Each environment mirrors production configuration closely enough to catch the real bugs—services, routing, feature flags—while running on safe test data so live customers and secrets stay untouched.

  4. 04 Shareable

    Everyone reviews the same living URL

    Developers, designers, and reviewers receive a shareable URL. They click through the actual change—layout, auth, edge cases—instead of screenshots, local builds, or “works on my machine.”

    Preview
    https://pr-482.preview.branchglass.dev
  5. 05 In sync

    New commits update the environment

    Push a fix, a copy tweak, a forgotten flag. Branchglass refreshes the preview automatically so reviewers always see the latest revision of the pull request—not yesterday’s build.

    Updates
    b4c19a Address review comments Updating

  6. 06 Ephemeral

    Merge or close, and it vanishes

    When the pull request is merged or closed, Branchglass removes the environment. Cloud spend returns to baseline. Nothing lingers, drifts, or becomes the next forgotten staging server.
