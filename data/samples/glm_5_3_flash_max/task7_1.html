Branchglass — How it works

How it works

A production-like environment for every pull request.

Branchglass connects to your repository and your cloud account, then runs the entire preview lifecycle for you — spinning up an isolated environment when a PR opens, keeping it in sync with every commit, and tearing it down the moment the branch is merged or closed.

The lifecycle of a preview environment

01

Connect your repo and cloud

One-time setup: authorize your Git provider and cloud account. Branchglass deploys with scoped, least-privilege credentials — no agents to install, no pipeline YAML to maintain.

02

Open a pull request

A webhook fires and Branchglass provisions an isolated environment for the branch — built in parallel with CI, without touching a single line of your existing setup.

03

Production-like, but safe

Each environment mirrors your production configuration — same service topology and settings — seeded with masked, disposable test data instead of real customer records.

04

Share one URL

Every environment gets a stable preview URL. Drop it on the PR so engineers, designers, and reviewers can click through the real change — not a screenshot or a staging queue.

05

Every commit, same URL

Push again and the environment updates itself — new build, same link. Reviewers always see the latest code, with no manual redeploys and no stale previews.

06

Merged or closed? It’s gone

The moment the PR is merged or closed, Branchglass destroys the environment and releases its cloud resources. Nothing lingers to surprise your next invoice.
