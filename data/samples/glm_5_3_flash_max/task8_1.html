How it works

From spec to shared mock in three steps

No servers to configure, no fixtures to maintain. Your contract does the work.

01

Bring your spec

Import an OpenAPI file, paste a URL, or sync directly from your repository. MorrowSpec reads your endpoints, schemas, status codes, and error shapes.

02

Get a working endpoint

A hosted mock goes live instantly with realistic data generated from your schemas — plus every defined error, and scripted test scenarios you can trigger on demand.

03

Keep it in sync

When the specification changes, the mock updates automatically — and your team sees exactly what changed. Everyone keeps building against the current contract.

Product

Everything a mock API should be

Built for the messy reality of parallel development — not just a pretty stub.

Import or repo sync

Drop in an OpenAPI file or URL, or point MorrowSpec at your repository and it keeps the mock aligned with the spec as it evolves.

Realistic responses

Data generated from your schemas: plausible values, consistent relationships, and pagination — never lorem ipsum, never an empty object.

Errors on demand

Every response defined in your spec is callable. Reproduce 404s, validation failures, and rate limits with a single request header.

Test scenarios

The mock rebuilds when the spec changes, with a clear diff of what moved. Frontend never chases a stale contract mid-sprint again.

Shared environments

One stable base URL per environment. Frontend, backend, QA, product — and CI — all work against the same hosted mock.

orders-api.yaml — OpenAPI 3.1 · 2.4.0 
openapi: 3.1.0
info:
  title: Orders API
  version: 2.4.0
paths:
  /orders/{orderId}:
    get:
      operationId: getOrder
      responses:
        "200":
          description: A single order
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Order"
        "404":
          $ref: "#/components/responses/NotFound"
components:
  schemas:
    Order:
      type: object
      properties:
        id:       { type: string }
        status:
          enum: [placed, shipped, delivered]
        total:    { type: number, format: double }
        placedAt: { type: string, format: date-time }

FAQ

Questions, answered

What do I need to get started?

An OpenAPI 3.x REST specification. Import a file, paste a URL, or sync from your repository — if the spec validates, MorrowSpec can have a hosted mock running in minutes.

How realistic are the generated responses?

Responses are generated from your schemas with plausible, internally consistent values, and they respect your defined status codes, headers, and error shapes. For anything that needs to be exact, test scenarios let you pin specific data and states.

What happens when our spec changes?

The mock updates automatically — new fields, new endpoints, changed enums — and the environment shows a diff of what changed, so nobody is caught mid-sprint by a silent surprise. Stale responses don’t linger.

Can my whole team use it?

Yes. Environments are shareable by URL with role-based access, so frontend, backend, QA, and product all hit the same mock — and CI pipelines can too, using scoped keys.

What does the private beta cost?

Nothing. MorrowSpec is free during the private beta. In exchange, we ask beta teams for honest feedback about what works, what’s missing, and what would make mocks a permanent part of their workflow.

Which API styles are supported?

The private beta initially supports OpenAPI-based REST APIs. Support for more protocols and spec formats — including GraphQL and gRPC — is on the roadmap after beta.
