How it works

From specification to shared environment in under five minutes

No hand-written stubs, no fixture drift. MorrowSpec reads the spec your team already reviews and keeps the mock in step with it.

STEP 01

Import or sync your spec

Drop in an openapi.yaml or connect a repository and let webhooks re-import on every merge to main.

OpenAPI 3.1 & 3.0 · Swagger 2.0 converter · GitHub, GitLab, Bitbucket, Bitrise

STEP 02

Get a hosted endpoint

Every operation gets a real URL with schema-aware payloads, consistent IDs and relationships that hold together across requests.

318 data responses · 46 error scenarios · 7 latency profiles

STEP 03

Keep it current

When the spec changes, MorrowSpec diffs it, flags breaking changes and regenerates only the affected responses.

8 breaking changes flagged this week · 3 drift alerts resolved

STEP 04

Share the environment

One URL per branch, with viewer, editor and owner roles so frontend, backend, QA and product work against the same behaviour.

FAQ

Questions teams ask before joining

What do I need to join the private beta?–

An OpenAPI 3.0 or 3.1 specification (Swagger 2.0 works through a converter) and a repo you can grant read-only access to, or a spec you can upload directly. No backend service is required — MorrowSpec generates responses from the schemas alone. Onboarding is a 15-minute call with a product engineer.

How realistic are the generated responses?+

Responses are derived from your schemas: types, formats, enums, patterns and examples are respected, and related resources stay consistent — a merchant ID returned by /v1/merchants resolves correctly in /v1/payouts. Each environment is seeded, so two runs of the same request return the same data unless you ask for a new seed.

Can I test failures and edge cases, not just 200s?+

Yes. Every operation ships with its documented error responses plus additional scenarios: expired tokens, validation errors, conflicts, rate limits, timeouts and a 12% flaky profile. You can pin a scenario per request with the x-morrowspec-scenario header, or set a default per environment so QA always gets the failing path.

How does the mock stay in sync with the spec?+

Connect a repository and MorrowSpec re-imports on every merge to main via webhook. Changed operations are diffed, breaking changes are flagged with an auto-mapping suggestion, and only affected responses are regenerated — typically in under ten seconds. Pull requests can create isolated preview environments on request.

What happens to our specification data?+

Specs are encrypted at rest and in transit, never used to train anything, and never shared between workspaces. Repo access uses a read-only deploy key or GitHub App installation that you can revoke at any time. Deleting a workspace removes its specs, environments and request logs within 24 hours.

Is there a CLI and a CI integration?+

Yes. The morrowspec CLI links repositories, promotes environments and exports assertions; the GitHub Action runs your integration suite against an environment and fails the build on unexpected status codes. Both are available to every beta workspace.

What does it cost after the beta?+

The beta is free and beta workspaces keep 12 months of the Team plan at no charge when general availability arrives. Planned pricing is $49 per environment per month with unlimited collaborators, and a free tier that includes one environment.
