Configuration reference 9 settings · applies per lane

Edit any of these values on a lane row in the Configuration tab. Saving writes through to the carrier app, dispute queue and storage indexer.

pod_signed_photo_required bool

When true, drivers must capture a clear photograph of the recipient's signed waybill. Block the delivery from being marked complete until the image passes QC. Adds ~1.6 min/stop on routes with high no-contact rate.

pod_doorstep_photo_required bool

When true, the driver photographs the package at the delivery location. Used as a fallback when signed proof is unavailable. Storage impact +0.4 GB / day / lane at 2 MP.

pod_id_scan_required bool

When true, requires an ID document scan for packages with declared value > $500. Contractually required on all MX→US import lanes. Setting false on a qualifying lane may breach carrier contract.

pod_customs_form_required bool

Required when the destination triggers customs clearance (US→PR, US→AK, US→HI, MX→US, CA→US). Auto-detected from route metadata; manual override exists for lane exceptions.

pod_min_resolution_mp enum

Minimum camera resolution in megapixels. Photos below threshold are rejected and the driver is asked to recapture. Recommended 2 MP for sign-offs; 5 MP for customs document scans.

pod_retention_days int

Days before files are purged from cold storage. Must be ≥ 28 to remain inside the standard customer-dispute window. Setting below 28 is allowed but flagged in audit.

pod_on_failure enum

What happens when a required file fails to upload within 90 sec of capture. block holds delivery; retry_3x re-attempts; allow_with_exception continues and queues manual review; skip drops the file silently (audit only).

pod_max_retry_count int

When pod_on_failure = retry_3x, how many times the carrier app reattempts the upload before escalating to allow_with_exception. Range 1–5; default 3.

pod_geo_stamp_required bool

When true, capture coordinates are embedded in file metadata. Used to validate drop-off location. Required for high-value lanes (LTD-2 and above). Default true on all lanes.

Policy spec · POD-CFG/v4.2

Lane file-capture policy reference

This policy governs the proof-of-delivery files that drivers must capture for each last-mile lane. Changes flow through three downstream systems when you save a lane row:

  • Carrier app — drivers see a new capture prompt at drop-off (5–20 sec added per required file).
  • Dispute queue — retention windows are recalibrated against the customer SLA of 28 days.
  • Storage indexer — files purged earlier than the SLA window are flagged for the audit log.

Required files

Each lane may require up to four file types. At minimum, a sign-off file (pod_signed_photo_required) is recommended on every commercial lane. ID-scan and customs-form requirements are derived automatically from the route metadata but can be overridden per lane.

Retention policy

The current customer-dispute window is 28 days from delivery. Setting pod_retention_days below 28 is permitted but flagged. The audit log records every lane where retention is under-spec, with the cost-of-exposure estimate.

Failure handling

pod_on_failure controls what happens when a required file fails to upload within 90 sec of capture. block is the strictest and is recommended for lanes with regulatory requirements; allow_with_exception queues manual review and is appropriate for routine commercial lanes.

Compliance gates

Lanes with declared value > $500 are automatically gated by pod_id_scan_required. Lanes crossing customs borders (MX→US, CA→US, US→PR, US→AK, US→HI) are gated by pod_customs_form_required. Both can be force-enabled; neither can be force-disabled without an explicit reviewer override.
