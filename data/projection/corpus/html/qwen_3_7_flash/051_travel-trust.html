Trust Model & Certification Registry

Nordic Passage implements zero-trust architecture rooted in mTLS device identity and hardware-bound signing keys. Every packet traversing a border checkpoint carries a verifiable attestation signed by the platform's root HSM (Hardware Security Module). The sections below describe the trust chain and list active certificates.

Each edge node ships with a certified TPM 2.0 module (Infineon SLB9672) factory-seeded with a unique RSA-4096 key pair during assembly at our Copenhagen fabrication lab. Private keys never leave the TPM. At first boot, the node authenticates to the orchestration plane via a challenge-response signed by its Attestation Key (AK). Only nodes whose measured Boot Loader Integrity (BLI) digest matches the known-good hash receive a Transport Signing Key (TSK) issued by the platform HSM. This is a direct implementation of Google's BeyondCorp model adapted for offline-capable border hardware.

Inspector workstations present X.509 client certificates issued by the NordPassage Intermediate CA (validity: 365 days, renewed automatically via ACME protocol). Passenger devices are optionally challenged — e-passports use BAC (Basic Access Control) derived from MRZ-encoded passport number, date of birth, and expiration date to derive session keys compliant with ICAO Doc 9303 Part 12. All session data passes through an ephemeral Diffie-Hellman exchange (X25519) with forward secrecy.

Every inspection record — passport scan, biometric comparison score, secondary-flag decision — is hashed with SHA-256 and appended to a Merkle tree stored immutably on the edge node's secure NAND partition. Root hashes are published daily to a public timestamping oracle (RFC 3161 conformant, operated by DigiCert). Cross-border agencies may verify the chain of custody by reconstructing the Merkle path from any leaf node using the published root hash. No cloud dependency is required for verification.

Nordic Passage holds valid ISO/IEC 27001:2022 certification (certificate no. DNV-CS-10247853, audited 2025-03-12 by Det Norske Veritas). Biometric processing operates entirely on-device under the GDPR's "technical and organizational measures" exception for legitimate public interest (Article 6(1)(e)) — no biometric templates are transmitted off-node. Under the EU AI Act (Regulation 2024/1689), the system is classified as minimal-risk because decisions are reviewable by trained inspectors and the system provides full algorithmic transparency documentation.
